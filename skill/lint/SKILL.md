# Lint — 知识图谱健康巡检

## Overview

定期对 `wiki/` 知识库进行健康检查，发现死链、孤岛页面、未同步索引和知识冲突。类似软件工程中的静态代码分析。

```
扫描 wiki/ 所有文件
  │
  ├── 索引一致性检查 → index.md 已注册 vs 文件实际存在
  ├── 双向链接健康检查 → 死链 + 孤儿页面
  ├── 知识冲突审查 → 标记为冲突的页面
  │
  ▼
输出结构化报告（绿/黄/红灯）
  │
  ▼
等待用户确认后执行修复
```

## 触发条件

- 用户输入 `/lint`、`/scan`、`/health`
- 用户说："检查知识库健康"、"看看 wiki 有没有问题"、"体检一下"

## 巡检流水线

### 第 1 步：索引一致性检查
1. 读取 `wiki/index.md` 全部内容
2. 扫描 `wiki/` 下所有 `.md` 文件
3. 找出：已注册但文件不存在的条目 + 文件存在但未注册的页面

### 第 2 步：双向链接健康检查
1. 扫描所有 `.md` 文件，提取所有 `[[双链]]`
2. 链接指向的页面不存在 → **死链**
3. 从未被任何其他页面引用 → **孤儿页面**
4. 排除 `index.md` 和 `log.md`

### 第 3 步：认知冲突审查
搜索所有文件中包含 `## 知识冲突` 的页面，提取冲突描述。

### 第 4 步：输出报告

```markdown
## 🩺 知识库健康体检报告 — YYYY-MM-DD

### ✅ 绿灯项
- [一切正常的项目]

### ⚠️ 黄灯项
- **N 个孤儿页面**：[列表]
- **N 个未同步索引**：[列表]

### ❌ 红灯项
- **N 个死链**：[来源] → [[不存在的目标]]
- **N 个未解决的知识冲突**：[页面名称]

### 🛠️ 建议行动
1. 是否自动修复未同步索引？
2. 是否处理知识冲突？
```

## 硬约束

- **仅读扫描** — 生成报告前禁止修改任何文件
- **手动确认** — 报告后等待用户确认再修复
- **静默日志** — 修复后在 `wiki/log.md` 追加记录

## 建议频率

- 每周 1 次保持知识库健康
- 每次大规模 Ingest 后跑一次
